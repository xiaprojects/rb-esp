# Host unit tests

Native (Linux/macOS) unit tests for firmware logic that does not need an ESP32:
selected sources from `main/` are compiled with the host compiler, ESP-IDF /
FreeRTOS / LVGL are replaced by the fakes in `stubs/`, and the suites run under
[Unity](https://github.com/ThrowTheSwitch/Unity) via CTest.

No ESP-IDF installation is required.

## Run

```sh
cmake -S test/host -B build/host-tests
cmake --build build/host-tests
ctest --test-dir build/host-tests --output-on-failure
```

Individual suites are plain executables: `./build/host-tests/test_ec11`.

Requirements: CMake ≥ 3.16 and a C compiler with GNU extensions (`-std=gnu17`,
the same dialect ESP-IDF uses).

## What is covered

| Suite | Firmware source | Subject |
|---|---|---|
| `test_madgwick`   | `RB/madgwick.c`          | IMU attitude filter: convergence, gyro integration, invariants |
| `test_guihelpers` | `RB/RB02_GUIHelpers.c`   | NMEA coordinate/checksum helpers, QNH suggestion, model string |
| `test_ems_parser` | `RB/RB04_NMEA_Parser.c`  | `$RBEMS` / `$RBCYL` engine-monitor sentence parser |
| `test_ec11`       | `RB/RB02_NavCore.c`      | EC11 rotary encoder state machine and EC11→touch mapping |
| `test_traffic`    | `RB/RB05_FlarmParser.c`, `RB/RB05_Traffic.c`, `RB/RB05_Radar.c` | FLARM / ADS-B traffic: sentence → store → traffic list and radar screens |

Tests named `test_known_issue_*` document firmware defects found while writing
the suite. They `TEST_IGNORE` themselves while the defect is present and become
ordinary assertions as soon as it is fixed, so they never block CI but are
visible in every run. One remains, in `test_madgwick`.

`test_traffic`'s **Regressions** section holds the assertions that used to be
`test_known_issue_*` markers and are now live. The comment on each records the
defect it pins, so a fix is not quietly undone:

| Pinned behaviour | Was |
|---|---|
| negative coordinates round-trip at every digit width | `'-'` seeded the accumulator with `-1`, so `-14025` read as `-85975` and wrapped to `-20439` |
| icon heading matches apparent motion | nose drawn at 136 deg while the blip slid at 43.9 deg |
| BLE fragments are reassembled | 20-byte notifications yielded no traffic at all |
| no phantom rows at any time of day | ten `+0FL 0NM` rows between 09:06 and 18:12 UTC |
| icons hidden outside the vertical filter | a climbing target kept its icon for ever |
| range label matches the drawn scale | zoom-out advertised 2.5x the real range |
| slots recycle across midnight | seconds-of-day stamps blocked recycling for an hour |
| 11th target dropped without reading past the array | `obstacles[10]` of a 10-element array |
| checksum does not corrupt the accumulator | `'*'` fed the accumulator until signed overflow |

## Simulating traffic input

`test_traffic` is an integration test: it replays recorded sentences through
`RB05_FlarmParser_ParseData()` — the same entry point the BLE and USB paths
call — and then asserts on what the traffic list and radar screens would draw.

### Fixtures

| File | What it is |
|---|---|
| `fixtures/flarm_session.nmea` | A verbatim Stratux capture (the one quoted in `RB05_FlarmParser.c`) followed by a synthetic continuation: aircraft move, one goes silent, one appears 67 s later, one triggers a proximity alarm. |
| `fixtures/dump1090_sbs.txt` | A dump1090 SBS-1 ("BaseStation", port 30003) capture: callsign, position and velocity arrive as separate records that must be merged per hex ident. |
| `fixtures/dump1090_traffic.nmea` | The above converted to `$PFLAA`, generated by `tools/sbs_to_pflaa.py`. |

The fixture's `$GPRMC` timestamps drive `datetime`, so traffic ages exactly as
it would on the device. Comment lines (`#`) are stripped on load.

### Transports

The two firmware entry points frame data differently, and the difference is
itself a source of bugs, so `sim/traffic_replay.c` can replay any fixture as:

* `REPLAY_LINE` — one whole sentence per call, as `RB_Usb.c` does after
  buffering the console to `\n`.
* `REPLAY_BULK` — one stream read carrying the whole buffer.
* `REPLAY_BLE` — MTU-sized fragments through `RB05_FlarmParser_FeedStream()`,
  which is what `RB05_ESP_Bluetooth.c` now does with each
  `ESP_GATTC_NOTIFY_EVT` payload.
* `REPLAY_BLE_NO_REASSEMBLY` — the same fragments handed straight to the
  parser, i.e. the old BLE path. Kept so the regression stays pinned.

`replay_set_clock()` lets a test age traffic out without feeding more data.
The parser logs a line per sentence; replay swallows that so output stays
readable — set `RB_TEST_VERBOSE=1` to see it.

### dump1090 / ADS-B

There is **no dump1090 parser in the firmware**: `RB05_GDL90Parser.c` is a stub,
`RB05_GDL90` is never defined, and the file is not in `main/CMakeLists.txt`.
ADS-B also carries absolute positions while `$PFLAA` carries positions relative
to ownship.

`tools/sbs_to_pflaa.py` does that conversion on the host, which lets dump1090
traffic drive the FLARM path the firmware already implements:

```sh
# Regenerate the fixture from a capture
tools/sbs_to_pflaa.py --in fixtures/dump1090_sbs.txt \
                      --out fixtures/dump1090_traffic.nmea

# Replay a live dump1090 into a device, in real time
tools/sbs_to_pflaa.py --host 127.0.0.1 --port 30003 --follow > /dev/ttyUSB0
```

Ownship defaults to the position used by the fixtures; override with
`--lat/--lon/--alt`. The script is also a working specification for the
firmware-side adapter, if ADS-B input is ever wanted on the device.

## Sanitizers

Some defects are only visible with instrumentation:

```sh
cmake -S test/host -B build/host-asan -DRB_SANITIZE=ON
cmake --build build/host-asan
ASAN_OPTIONS=detect_leaks=0 ./build/host-asan/test_traffic
```

Both the signed-integer overflow and the out-of-bounds read this used to find
in `RB05_FlarmParser.c` are fixed; the suite is expected to be clean. Two of the
regression tests above can only be fully verified this way, since the defects
they pin were undefined behaviour rather than wrong output.

## How it works

* `main/RB/RB02.h` ends with a deliberate `#error` so casual cloners use the
  official binaries. The harness defines `RB_HOST_TEST`, which lifts that guard
  and nothing else.
* `stubs/include/` shadows the ESP-IDF, FreeRTOS, driver and LVGL headers. It is
  placed first on the include path. Real project headers (`sc16is750.h`,
  `RB02_Config.h`, …) are used as-is; only the thin HAL underneath is faked.
* `stubs/esp_stubs.c` / `stubs/lvgl_stubs.c` hold the fake implementations.
  `stubs/host_stubs.h` is the test-facing control API (fake clock for
  `esp_timer_get_time()`, last `lv_label_set_text()` string, …).
* `main/RB/BuildMachine.h` is included by the firmware headers and must exist;
  copy any `BuildMachine-Template-*.h` there if it is missing. Feature flags a
  suite needs beyond that (`RB_ENABLE_NavCore`, `RB_ENABLE_EMS`) are set per
  target in `CMakeLists.txt`.
* **That file decides which suites can build.** `RB02_Defines.h` includes it by
  quoted path, so a quoted include always resolves next to `RB02_Defines.h` and
  no `-I` ordering can shadow it. `test_traffic` needs `RB02_ESP_BLUETOOTH` or
  `RB_ENABLE_USB_FLARM` (that is what defines `RB05_Flarm_SERIAL`) and needs
  `RB_ENABLE_TRK` **off**, because `RB_ENABLE_TRK` makes `RB05_Radar.c` reach
  for `singletonConfig()->ui.Gyro` and drag the NVS stack into a screen test.
  `CMakeLists.txt` parses the header and prints what it found:

  ```
  -- BuildMachine.h: traffic=TRUE RB_ENABLE_TRK=FALSE
  ```

  A suite it cannot support is skipped with the reason, so `ctest` reporting 4
  tests instead of 5 is expected on a non-traffic config, not a failure. The
  version committed to git is one of those: it enables `RB_ENABLE_TRK` and no
  Bluetooth. CI pins a traffic-capable config instead and fails if a suite was
  skipped (`.github/workflows/host-tests.yml`).

## Adding a suite

1. Create `test/host/test_<name>.c` with `setUp`, `tearDown` and a `main` that
   calls `UNITY_BEGIN()` / `RUN_TEST()` / `UNITY_END()`.
2. Add `rb_add_test(test_<name> "${RB_MAIN}/RB/<source>.c" ...)` to
   `CMakeLists.txt`, plus any `target_compile_definitions` the source needs.
3. Build. If the compiler asks for a header or the linker for a symbol that is
   not in `stubs/`, add the smallest possible fake there; do not vendor ESP-IDF.

Files that are `#include`d as `.c` from another translation unit (for example
`RB04_EMS_Setup.c` from `RB02_Setup.c`) can only be tested together with their
includer.

A test that needs a fixture should build its path from `RB_TEST_DIR`, which
CMake defines as this directory, so the binary runs from anywhere.
